# Hoshino: Realm of Watercolor

《星野：水彩之境》是一个使用 **TypeScript、Vite 和 Three.js** 构建的浏览器 3D 叙事探索 Demo。玩家与星灵伙伴进入失去色彩的手绘本世界，通过行走和故事互动，让地面、植被、溪水、花树与远山逐步从铅笔线稿恢复为水彩画面。

> 当前状态：`v0.1.0-rc.1`，单场景三节点流程已接通，可通关、重置并再次游玩。
>
> 本项目是可运行的技术与人机交互原型，不是完整游戏，也不是通用游戏引擎。
>
> 仓库已于 2026-11-19 设为公开；许可证等发布材料仍待补齐，见[发布清单](docs/OPEN_SOURCE_CHECKLIST.md)。

## 项目定位

本项目用于验证一个核心体验：**玩家走过之后，世界真的因为玩家而留下颜色。**

它同时提供三个可复用的学习样本：

- Three.js 中基于世界坐标遮罩的持续染色与跨材质共享 uniforms。
- 第三人称探索、轻量叙事状态机、伙伴跟随、VFX 和完整重置的工程组织。
- 多 Agent 按模块边界、分支、PR 和验收标准协作的开发流程。

## 当前已实现

- 第三人称移动：WASD/方向键、Shift 小跑、平滑转向、地形贴地和基础碰撞。
- 第三人称镜头：左键拖拽旋转、滚轮缩放、平滑跟随和基础地形避让。
- 世界染色：512×512 CanvasTexture、世界 XZ 到 UV 映射、脚下永久路径和节点扩散。
- 水彩材质：纸色、铅笔排线、程序化纸纹，以及 8 类世界材质共享同一组 reveal uniforms。
- 单场景关卡：96m×96m 区域、起伏地形、蓝花坡、溪流、踏石、花树和界外远山。
- 三节点故事：蓝花坡 → 溪流 → 花树，包含目标提示、短对话与三枚可收集星屑。
- 星灵伙伴：悬浮跟随、目标引导和远距离/卡住回收。
- 结局表现：花树扩散、远山显色、花瓣、涟漪、镜头拉远和延迟结局卡片。
- 完整重置：不刷新页面即可重新开始；任务、星屑、世界染色、镜头和活跃 VFX 复位。
- 工程与验收：严格 TypeScript、单元测试、Playwright e2e、真 GPU 性能门禁和调试面板。

### 当前不包含

- 战斗、背包、抽卡、多人、账号、后端、云存档和多地图。
- localStorage 存档、手柄、手机触控和完整键位设置。
- 实时阴影、完整刚体物理、导航网格、GLB/glTF 模型加载管线。
- 角色骨骼或四肢走跑动画；当前角色为程序化低模，随移动更新位置和朝向。
- 正式音频：虽然代码包含可选 `AudioManager`，但主程序未接入，当前游戏静音。

`docs/V02_VISUAL_WORKFLOW.md` 描述的更密森林、小径、角色动作和多层花瓣由独立的 `visual/*` 分支开发，尚未合并到默认分支 `main`，因此不属于当前克隆即可运行的功能清单。

## 适用场景

- 学习 Three.js 自定义材质、CanvasTexture、世界坐标遮罩和轻量后期。
- 制作水彩/线稿风格的交互叙事或独立游戏视觉原型。
- 作为多 Agent 小型 Web 3D 项目的分工、集成和测试参考。
- 研究故事事件、镜头、VFX、伙伴和世界状态如何解耦。

不适合作为需要完整物理、大型地图、生产级动画管线或现成游戏系统的直接解决方案。

## 快速开始

### 环境

- Node.js `>=20.19.0`
- npm
- 支持 WebGL2 的桌面浏览器
- 当前主要在 Windows + Chrome/Chromium 环境验证；其他平台未系统测试

### 克隆与运行

```bash
git clone https://github.com/TheNorth7747/Hoshino-Realm-of-Watercolor.git
cd Hoshino-Realm-of-Watercolor
npm ci
npm run dev
```

打开终端输出的地址，默认为 `http://127.0.0.1:5173/`。

### 操作

| 操作     | 按键                       |
| -------- | -------------------------- |
| 移动     | WASD 或方向键              |
| 小跑     | Shift                      |
| 旋转镜头 | 按住鼠标左键拖拽           |
| 缩放镜头 | 鼠标滚轮                   |
| 节点互动 | E                          |
| 推进对话 | E 或点击                   |
| 重新开始 | 结局卡片中的“重新进入绘本” |

### 构建与预览

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`，可作为静态站点部署。项目运行时不需要后端或外部素材服务。

## 调试与测试

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
npm run test:e2e:install
npm run test:e2e
```

真 GPU 性能门禁：

```bash
npm run test:e2e:hw
```

该脚本使用系统 Chrome 和硬件加速，要求本机环境支持。默认 e2e 使用 SwiftShader，适合功能回归，不适合作为真实 GPU 帧率结论。

打开 `http://127.0.0.1:5173/?debug=1` 可查看性能、玩家、故事、伙伴、VFX 和染色遮罩，并使用节点调试按钮。调试功能不属于正常玩家流程。

详细说明见[开发与接入指南](docs/DEVELOPMENT.md)。

## 核心流程

```text
进入线稿世界
  → 行走留下永久彩色路径
  → 蓝花坡互动并生成星屑
  → 溪流互动并生成星屑
  → 花树互动，生成第三枚星屑
  → 靠近并收集花树星屑
  → 花树/远山显色 + 花瓣 + 镜头拉远
  → 2.5 秒后出现结局
  → 不刷新页面重新开始
```

注意：前两个节点的星屑可以漏收；当前只有花树星屑是结局的硬门槛。不要将其误解为“必须集齐 3/3 才能通关”。

## 验证与性能口径

最终验收报告记录：**24 个单元测试文件、272 个单元用例和 32 个默认 e2e 用例通过，AC-01～12 全部通过**。报告基线为 `e666dc6`；其后没有改变核心玩法和渲染逻辑。当前开源整理更新了文档、版本与公开元数据，正式发布仍应在最终提交上重新执行质量门禁。

报告还包含一次 RTX 3060 Laptop 环境的历史性能采样，以及 SwiftShader 下的 10 分钟稳定性观测。不同设备、浏览器和后续版本的结果可能不同；请以[最终验收报告](src/tests/A6_ACCEPTANCE_REPORT.md)的测试条件为准，不将单个数字理解为普遍性能保证。
